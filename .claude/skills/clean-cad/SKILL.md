# clean-cad: 깔끔한 CAD 형상을 얻는 방식

깔끔한 형상은 치수만으로는 나오지 않는다. 아래 세 가지가 있어야 한다.
1. **디자인 언어**: 어떤 선, 단면 계열, 모서리 처리로 만들지
2. **단면 설계**: 로프트에 들어갈 단면을 2D로 먼저 설계하고 확인
3. **검토 루프**: 렌더를 보고 체크리스트로 스스로 비평

G0는 규정 치수만 주고 만들어서 차체가 녹은 덩어리처럼 보인다(아래 진단표).
이 스킬은 text-to-cad F1 모델(`third_party/text-to-cad`, MIT)의 방식을 우리 CadQuery 코드와 CFD 제약에 맞춰 정리한 것이다.

| 참고 문서 | 언제 읽나 |
|---|---|
| [references/prompt-template.md](references/prompt-template.md) | 사용자가 프롬프트 쓰는 법을 물을 때, 요청에 빠진 정보가 있을 때 |
| [references/design-rules.md](references/design-rules.md) | 형상을 만들거나 고치기 전에 (필수) |
| [references/review-checklist.md](references/review-checklist.md) | 렌더를 보고 검토할 때 (필수) |

## 지금 모델이 지저분한 이유 (2026-10-19 진단, G0/G1)

| 보이는 문제 | 원인 | 규칙 |
|---|---|---|
| 차체가 녹은 덩어리, 울퉁불퉁한 음영 | 노즈부터 꼬리까지 초타원 로프트 하나. 단면 수치를 손으로 넣음. 성격선(어깨선·크리스)이 없음 | D1, D2, D3 |
| 날개가 두꺼운 판, 끝이 칼로 자른 듯함 | 일정 단면을 압출함. 엔드플레이트는 박스 | W1~W4 |
| 바닥이 얇은 판, 모서리가 각짐 | 다각형 압출 | E1, E2 |
| 바퀴가 원통 | 원통에 필렛만 줌 | T1 |
| 헬멧이 붙인 공, 부품끼리 겹쳐만 있음 | 기본 도형을 보이게 사용. 이음부 처리 없음 | E3, J1 |

## 작업 순서 (Claude가 따른다)

1. **브리프 확인**: [prompt-template.md](references/prompt-template.md)의 항목(목적, 충실도, 기준, 디자인 언어, 범위, 합격 기준) 중 빠진 것만 확인한다.
   결과에 큰 영향을 주는 것은 묻는다. 나머지는 가정으로 적고 진행한다.
2. **스펙 먼저**: 치수, 디자인 선(어깨선, 크리스), 단면 계열, 반경을 `CarParams`나 모듈 상단의 설계 표에 모은다.
   부품 함수 안에 숫자를 흩어 두지 않는다.
3. **단면을 2D로 먼저 본다**: 3D로 로프트하기 전에 세 가지를 그림으로 그려 직접 확인한다.
   - 키프레임 표
   - 보간한 단면 몇 개를 겹친 그림
   - 평면도·측면도 실루엣

   선이 꺾이거나 출렁이면 3D로 가지 않는다.
4. **3D 생성**: [design-rules.md](references/design-rules.md)를 따른다. **한 번에 한 부품씩** 만든다.
5. **QA**: `python scripts/build_car.py --half [--g1|--fia]`를 돌린다.
   규정 점검(기준 볼륨 포함)과 `cad/qa.py`(로프트 이탈, 양의 부피, 불리언 적합성, STL 닫힘, 부착)가 모두 OK여야 한다. NG가 있거나 계산에 실패하면 통과가 아니다.
   날개를 바꿨다면 X 모드(`--fw-flap-delta -10 --rw-flap-delta -25 --name <이름>_xmode`)로도 돌린다.
6. **렌더 검토**: `python scripts/render_car.py <이전> <이후>`로 6면을 나란히 그리고 직접 연다.
   [review-checklist.md](references/review-checklist.md) 항목마다 판정한다. 렌더는 한 번 보고 끝내지 않는다. 고친 부분은 그 부분이 잘 보이는 시점으로 다시 확인한다.
7. **보고**: 무엇을 바꿨는지, 실제로 돌린 검사, 확인하지 않은 항목, 전후 그림을 보고한다.
   G0 기준 형상을 건드리지 않았다면 baseline STL MD5가 그대로인지도 보인다.

## 지키는 제약

- **G0는 고정이다.** grid 연구의 기준이다. 새 형상은 G1/G2 옵션(`--g1`, `--fia`)으로만 만든다.
- **CFD에 쓸 수 있어야 한다.**
  - 부품마다 닫힌 고체로 만들고 STL을 따로 둔다.
  - 뒷전은 유한 두께(1.2 mm 이상)로 만든다.
  - 해당 격자 레벨에서 해상되지 않는 장식(약 2 mm 이하의 패널 틈, 볼트, 루버 같은 작은 구멍)은 넣지 않는다.
  - 내부 유로가 없으면 흡입구는 막힌 오목면으로 만든다.
- **규정 기준 볼륨 안에 있어야 한다(2026-10-21부터 강제).** G0를 뺀 모든 형상은 `build_car.py`의 기준 볼륨 검사(`cad/regvol.py`, App.1 본문 그대로)를 모두 통과해야 하고, NG면 빌드가 exit 1로 끝난다.
  - 설계 방식은 [design-rules.md](references/design-rules.md) R1~R5를 따른다. 핵심은 "허용 공간을 먼저 그리고 그 안에 설계"하는 것이다(R1).
  - 액티브 에어로 플랩은 기본과 X 모드 둘 다 확인한다(R4).
  - 새 부품이 아직 구현하지 않은 기준 볼륨에 걸리면, 먼저 그 볼륨을 `cad/regvol.py`에 추가하고 검사 줄을 만든다.
  - FIA CAD 파일로만 정의된 볼륨에 걸리는 부품은 넣지 않는다. 넣어야 하면 묻는다(R5).
- **지정한 특징을 조용히 빼거나 줄이지 않는다.** 반경, 슬롯 간격, 선 위치가 그렇다. 안 되면 보고하고 결정을 묻는다.
- **`third_party/text-to-cad/`는 읽기 전용이다.** 수치를 가져올 때는 좌표를 변환하고(x_우리 = −x_그쪽, 그쪽은 휠베이스 3600 mm), 출처를 적는다.

# 렌더 검토 체크리스트

형상을 바꾼 뒤에 쓴다. 체크리스트 항목마다 **OK / 문제 / 확인 못 함**으로 판정하고, 판정을 보고에 적는다.
검사가 통과했다고 형상이 맞다는 뜻은 아니다. text-to-cad는 이 단계를 "blind critic"이라 부른다. 처음 보는 사람처럼 흠을 찾는 검토다.

## 렌더 만들기

```bash
python scripts/build_car.py --half --fia                  # 또는 --g1, --details
python scripts/render_car.py fia2026_half                 # 6면(앞 3/4, 뒤 3/4, 옆, 위, 아래, 정면)
python scripts/render_car.py baseline_half fia2026_half   # 전후 나란히
```

- 렌더 PNG는 **직접 열어서 본다.** 파일이 생겼다고 끝내지 않는다.
- 수정한 부품은 그 부품이 잘 보이는 시점으로 확대해서 한 번 더 본다. 예: 엔드플레이트는 바깥쪽 아래에서 본다.
- 확대 시점이 필요하면 pyvista 카메라를 지정하는 짧은 스크립트를 임시로 만든다.
- matplotlib 6면 그림은 면 정렬이 부정확해서 언더컷과 휨 판정에는 쓰지 않는다.
- 참고 이미지가 있으면 **같은 시점**으로 렌더해서 나란히 놓는다.

## 전체 인상 (먼저 3초 보고 판단)

- [ ] 한 대의 차로 읽히는가? 부품마다 스타일이 달라 조립품처럼 보이지 않는가(L1~L3)
- [ ] 녹은 덩어리처럼 보이지 않는가? 차체에 읽히는 선(어깨선, 크리스)이 있는가(D3, L4)
- [ ] 비율: 사이드포드, 엔진커버, 노즈의 크기 관계가 참고 이미지와 비슷한가

## 표면

- [ ] 음영에 물결이나 셰브론 무늬(단면 간격마다 반복되는 굴곡)가 없는가(D1, D2)
- [ ] 단면보다 튀어나온 혹이나 부풂이 없는가? 이탈 검사 수치도 함께 본다(D5)
- [ ] 성격선이 면 한가운데서 사라지지 않고 다른 선이나 경계로 이어지는가(L4)
- [ ] 의도하지 않은 날카로운 꺾임이나 톱니 모서리가 없는가(D3 너클 반경)

## 가장자리와 끝

- [ ] 칼로 자른 듯한 끝(날개 끝, 판 끝, 바닥 모서리)이 보이지 않는가(W3, E1, E2)
- [ ] 엔드플레이트와 판 부품의 가장자리가 둥근가(W4)
- [ ] 보이는 곳에 박스, 원통, 구가 그대로 있지 않은가(L6)

## 날개

- [ ] 요소들이 같은 계열로 보이고 코드와 간격이 일정한 리듬으로 줄어드는가(L5)
- [ ] 슬롯이 보이고 막히거나 겹치지 않는가? 수치는 규정 점검으로 확인(W2)
- [ ] 스팬 방향으로 형상이 변하는가? 일정 단면 판처럼 보이지 않는가(W1)

## 이음

- [ ] 부품끼리 겹친 자리에 틈, 단차, 비집고 나온 면이 없는가(J1)
- [ ] 아랫면: 바닥, 사이드포드, 디퓨저 이음이 깨끗한가(아래 시점 필수)

## CFD 관점

- [ ] 2 mm 이하의 틈이나 장식이 생기지 않았는가
- [ ] 바퀴와 차체 사이 간극이 규정 점검 기준(10 mm 초과)을 지키는가
- [ ] 부품별 STL이 닫혀 있는가(`qa` 결과)

## 보고 형식 예

```
검토: fia2026_half, 렌더 6면 + 사이드포드 확대(앞 아래 3/4)
- 전체 인상 OK
- 표면: 사이드포드 윗면 X 2300 부근 물결 1개 (문제) → 키프레임 6과 7 사이 보간 확인 필요
- 가장자리 OK
- 날개: 확인 못 함 (이번 변경 범위 밖)
- 검사: build_car.py --fia 전 항목 OK, 사이드포드 이탈 8.2 mm
```

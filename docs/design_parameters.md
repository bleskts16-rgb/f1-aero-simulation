## 3. 원칙

1. **키프레임 표 + 변형 모드.** 부품은 이미 키프레임 표로 만들어져 있다(`G1_FW_SPAN`, `G1_RW_SPAN`, G1 사이드포드 단면 목록, `G1_WB_*`).
   설계 변수는 표의 값을 직접 바꾸지 않고, 정해진 모양의 변형(전체 이동, 바깥쪽 비틀림, 구간 높이 변화 등)을 더하는 계수다. 표 사이는 지금처럼 PCHIP으로 이어서 형상이 매끄럽다.
2. **변수는 물리적 의미가 있게.** 각도[°], 높이[mm], 폭 배율처럼 해석 결과를 읽을 수 있는 단위로 둔다.
3. **규정이 범위를 정한다.** 각 설계는 빌드할 때 기준 볼륨과 형상 규칙 검사를 통과해야 하고, 실패하면 자동으로 탈락한다. 범위는 "기준점에서 규정 여유"를 보고 정한다.
4. **G1과 G2는 같은 변수를 쓴다.** HF용 G2는 같은 변수 벡터로 만든 형상에 변하지 않는 디테일을 더한 것이다(§7).
5. **해석마다 커밋과 변수 값을 기록한다.** `case.json`에 git 커밋과 Δ 벡터를 남겨, 형상 폴더가 덮어써져도 다시 만들 수 있게 한다.

## 6. 해석 계획 (제안)

1. **스크리닝**: 기준점과 각 변수 ± 끝값으로 1회씩, 2 × 20 + 1 = 41회를 grid2 L1로 해석한다. 영향이 큰 6~8개를 고른다.
2. **본 DOE**: 고른 변수로 라틴 하이퍼큐브 LF 약 60개와 HF 10~15개(LF 점의 부분집합)를 만든다.
3. **LF 신뢰도 먼저**: 10-20에 grid2 L1이 설계 차이를 기준 격자의 절반 정도만 잡았다. 대량 생산 전에 설계 두 개를 L1·L2·L3로 비교한다(L2 이상은 이 회사 PC 메모리로 불가).

해석 시간: 이 회사 PC에서 G1 L1 1회는 약 3시간이라 41회면 약 5일(123시간)이다. 집 PC는 더 빠를 것으로 보지만 아직 측정하지 않았다.

## 7. 충실도와 HF 형상 (G2)

| 수준 | 형상 | 격자 | 용도 |
|---|---|---|---|
| LF | G1 | grid2 L1 | 대량 표본 |
| MF(선택) | G1 | grid2 L3 | 격자 오차만 분리 |
| HF | G2 | grid2 L3~L4 | 실제 차에 가까운 값 |

G2는 같은 설계 변수로 만든 G1 형상에 **변하지 않는 디테일**을 더한다. 후보는 이렇다.
- 열린 사이드포드 흡입구와 막힌 덕트
- 바닥 가장자리 형상(RS-FLOOR-STEP)
- 디퓨저 스트레이크
- 앞뒤 브레이크 덕트와 휠 스쿱(App.1 §28~30)
- 날개 거니와 플랩 행어
- 곡률 반경 규칙을 지키는 둥근 모서리

LF와 HF 형상이 크게 다를수록 두 데이터의 상관이 약해진다. 그래서 디테일은 변수로 두지 않고, MF 단계로 격자 오차와 형상 디테일 효과를 따로 본다.
G2 HF는 디테일 때문에 격자가 커서 집 PC나 다른 자원이 필요하다.

## 8. 구현 계획

1. `CarParams`에 위 Δ 필드를 기본값 0으로 추가한다(기존 `fw_flap_delta`, `rw_flap_delta`, `ride_height_*`는 그대로 쓴다).
   G1 함수가 Δ로 키프레임 표를 변형한다. Δ = 0이면 G1 v3와 같은 STL이 나와야 한다(MD5 확인).
2. `scripts/build_designs.py designs.csv`: 설계 목록을 읽어 형상 폴더(`cad/out/doe/<id>_half`)를 만든다. 검사 실패는 표에 표시하고 건너뛴다.
3. `make_cfd_case.py`가 `case.json`에 git 커밋, 형상 폴더, Δ 벡터를 기록한다.
4. 수동 계산한 형상 규칙 세 가지를 자동 검사로 옮긴다. 나머지 규칙(곡률, 단면 개수)은 순서대로 추가한다.

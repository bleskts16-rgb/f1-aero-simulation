# 참고 자료: text-to-cad F1 컨셉카

- 원본: [earthtojake/text-to-cad](https://github.com/earthtojake/text-to-cad) `models/f1`, `skills/cad`
- 고정 버전: commit `2457312` (2026-10-11). 사본은 [third_party/text-to-cad](../../third_party/text-to-cad/)에 있다(MIT, 수정하지 않음, 실행하지 않음).
- 이 문서는 2026-10-16에 집 PC에서 작성했다.

## 1. 무엇인가

AI 에이전트가 build123d(OpenCascade) Python 코드를 써서 CAD를 만드는 플러그인이다. 구성은 두 가지다.
- 스킬 문서(`SKILL.md`): 에이전트에게 작성·검증 규칙을 알려 준다.
- `cadgen` 도구: 빌드, 뷰어, 측정을 맡는다.

`models/f1`은 그 방식으로 만든 **보여주기용** F1 컨셉카다. 부품 28개, 약 13,400줄이다.
- 형상의 기준은 공력 검증이 아니라 디자인 규칙(재질, 선, 비율)이다.
- 치수는 2022~25 규정과 비슷하다. 휠베이스 3600 mm, 폭 2000 mm, 18인치 휠이다. 우리 모델은 2026 규정(휠베이스 3400 mm, 폭 1900 mm)을 따른다.
- 좌표계가 다르다. 그쪽은 X 전방 +, Y 왼쪽 +이고, 원점은 같다(앞차축, 노면).
  - **x_우리 = −x_그쪽**
  - Y와 Z는 한쪽 |Y| 기준으로 그대로 쓴다.

## 2. 이미 가져온 것 (2026-10-16)

| 가져온 것 | 원본 | 우리 쪽 위치 |
|---|---|---|
| 정밀 경계 상자(제어점이 아닌 실제 곡면 기준) | `surfaces.obox` | `cad/qa.py: tight_bbox`. 규정 점검에 사용 |

| 로프트 이탈 검사 | `surfaces.loft_escaped` | `qa.loft_local_escape`. 원본은 로프트 전체 상자로 비교하지만, 우리는 **이웃 단면 사이 구간마다** 비교한다 |

| 형상 변경 후 스냅샷을 직접 보고 검토 | skill: snapshot review | 렌더를 6면으로 확장(**아랫면** 추가) |

로프트 이탈 기준(30 mm)은 baseline 차체로 정했다.

| 매개화 | spine | sidepods |
|---|---|---|
| centripetal (현재) | 11.1 mm | 22.2 mm (아래쪽, 바닥 자르기로 제거됨) |
| chord length (이전) | **161.7 mm** (꼬리, X 3550) | 51.4 mm |
| uniform | 67.1 mm | 73.0 mm |

전체 상자로만 비교하면 chord length의 꼬리 부풂이 27 mm로만 보인다. 그래서 구간별 검사로 바꿨다.

## 3. 나중에 쓸 것: G1 형상 개선

### 3.1 바닥: 2026 규정에는 벤추리 터널을 그대로 쓰지 않는다 (2026-10-16 정정)
처음에는 이 모델의 벤추리 터널 바닥을 G1의 1순위로 적었다. 그런데 **2026 규정은 평평한(flat) 바닥과 더 크고 긴 디퓨저로 돌아간다.** text-to-cad 모델은 2022~25형 그라운드 이펙트 바닥이다.
근거:
- [motorsport.tech, 2026 aero regulations part 1](https://motorsport.tech/formula-1/f1-2026-aero-regulations-in-focus-part-1-back-to-the-future): "return to the more benign 'flat' floor and diffuser, albeit upsized from the 2021 dimensions", 바닥 입구가 훨씬 낮아짐
- 언론 요약: 바닥이 앞 끝부터 디퓨저까지 사실상 평평하다

그래서 현재 G0의 평판 바닥과 디퓨저 구성은 방향이 맞다. 아래 수치표는 이렇게 쓴다.
- **디퓨저**(스트레이크, 확장 비율)와 바닥 가장자리 처리에만 참고한다.
- 터널 형상은 2026에서는 쓰지 않는다.
- 2026 바닥과 디퓨저의 정확한 기준 볼륨은 규정 PDF(App.1 §4)로 확인한다.

수치표는 [ttc_f1_floor.json](ttc_f1_floor.json)과 [그림](../figures/ttc_f1_floor_tables.png)에 있다. `scripts/extract_ttc_reference.py`가 원본을 실행하지 않고 파싱해서 만든다.
위치는 s = x / 휠베이스(3600 mm)로 정규화했다. 0이 앞차축, 1이 뒤차축이다.

| 항목 | 값 |
|---|---|
| 터널 지붕 높이(킬 아래면 기준) | 입구 94 → 최고 208 (s≈0.03) → **스로트 104 (s≈0.44)** → 디퓨저 시작 228 (s≈0.87) |
| 스로트/입구 최고 비 | 약 0.50 |
| 디퓨저 시작/스로트 비 | 약 2.2 |
| 킬(중앙 평면) 반폭 | 172 → 최대 360 (s≈0.47) → 158 |
| 바닥 반폭 | 최대 892 (s≈0.53), 코크보틀로 528까지 좁아짐 |
| 바닥 가장자리 아래 선(Z) | 34 → 60 (디퓨저 시작) → 44 |
| 펜스 | 4개, 루트 코드 1080 mm, 아래 끝 Z 30→63, 캠버 0.02→0.074 |
| 디퓨저 스트레이크 | 3개, 출구 Z 124 / 166 / 208 |

**주의**
- 그쪽 `FLOOR_LE_X = +780`(그쪽 좌표)은 앞차축보다 **780 mm 앞**이다. 그런데 같은 파일의 주석은 "앞바퀴 선 뒤"라고 한다. 수치와 주석이 맞지 않는다.
  실제 F1과 2026 규정에서 바닥은 앞바퀴 뒤에서 시작한다. 그러므로 **절대 위치는 쓰지 말고**, 입구 → 스로트 → 확장의 **형상 법칙과 비율**만 우리 바닥 범위에 다시 매핑한다.
  우리 바닥 범위는 X 420부터 XR+165까지이고, 2026 규정 App.1 §4 안에 있다.
- 공력으로 검증된 값이 아니다. 우리 CFD로 비교해서 확인해야 한다.
- 바닥이나 디퓨저를 바꾸는 일은 **격자(grid2)가 정리된 다음에** 한다. 형상과 격자를 동시에 바꾸면 CL 변화의 원인을 나눌 수 없다.

### 3.2 만드는 기법
- **단면에 날카로운 모서리 유지** (`floor._poly`, `_corner_pts`, `_dedup`):
  - 스플라인 단면에 꼭짓점마다 반경 7~11 mm의 작은 원호를 직접 넣고, 직선 구간을 잘게 나눈다. 그러면 평평한 킬, 가파른 터널 벽, 아치형 지붕이 뭉개지지 않는다.
  - 1.6 mm보다 가까운 점은 지운다. 남겨 두면 OCC가 "BRep_API: command not done" 오류로 실패한다.
- **로프트 대체 경로** (`surfaces.loft_solid`): 매끄러운 로프트 → 이탈하면 ruled 로프트 → 그것도 실패하면 이웃 단면 쌍마다 ruled 로프트를 만들어 합친다. 결과는 ruled 로프트와 같고, 견고성만 높인다.
  - OCC 빌더는 넘겨받은 형상을 바꿀 수 있다. 그래서 같은 단면을 두 번 쓸 때는 복사해서 쓴다.
- **불리언 후 복구** (`surfaces.repair`): ShapeFix로 면 하나의 트림 오차를 고친다. 다음 불리언이 엉뚱한 곳에서 실패하는 것을 막는다.
  - 단, 형상 치수를 바꾸면 안 된다. 쓰면 QA로 전후를 비교한다.
- **다중 엘리먼트 날개 규칙** (`spec.py`):
  - 코드 비 0.80, 슬롯 간격 비 0.90을 기하급수로 적용한다.
  - 받음각 증분은 10, 10, 11, 12°처럼 점점 커지게 한다.
  - 뒷전 두께는 1.2 mm로 통일한다. CFD에서는 뒷전이 닫혀 있어야 메싱이 안정적이다.
- **필렛 사다리** (`safe_fillet`): 큰 반경부터 시도해서 성공한 반경을 쓴다.
  - 그쪽 스킬 문서도 "요구된 반경을 조용히 줄이지 말라"고 경고한다. 우리는 필렛이 필요하면 반경을 명시하고, 실패하면 보고한다.

## 4. 가져오지 않는 것
- 플러그인과 `cadgen` 런타임 자체. 텔레메트리가 기본으로 켜져 있고, 두 PC에 따로 설치해야 하며, 우리 CadQuery 코드와 따로 논다.
- 재질, 색상, 애니메이션, 내부 부품(엔진, 기어박스, 콕핏). CFD와 무관하다.
- 1~3 mm 디테일(패널 틈, 볼트, 작은 필렛). snappyHexMesh 셀 수가 폭증한다.
